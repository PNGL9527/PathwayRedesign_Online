# Pathway Redesign

**医护团队与服务设计师共同讨论患者体验的交互式工作区。**

基于 Peng Lu 的产品服务系统设计硕士论文：

*Acknowledging the Voice of Service Design(ers) in Healthcare and Vice Versa: Exploring a Dialogic Tool as a Boundary Object for Patient Experience Improvement.* 指导教师 Daniela Sangiorgi，学年 2021/2022。

## 立即使用

双击 `Pathway_Redesign_Standalone.html`，用 Chrome、Edge、Firefox 或 Safari 打开。此文件已包含程序、样式与示例，不需安装软件，也不需要网络。

右上角切换 **中文 / EN**。界面切换语言时，项目证据、引语和团队自行定义的评分标准保持原文。

在浏览器打开 `index.html` 需要 HTTP 服务。它是 GitHub Pages 的入口；本地直接双击时，请使用上面的独立 HTML 文件。

## 主要功能

| 视图 | 用途 |
| --- | --- |
| 路径工作区 | 中央路径图，左侧体验设计，右侧临床与管理。选择节点、子区段或分流，两侧证据同步切换。 |
| 证据矩阵 | 横向比较所有分流的评分及原始观察值，点击分流返回工作区。 |
| 讨论优先项 | 完整评分较低的分流排在前面；评分不完整的分流单独保留。 |
| 共同设置 | 修改目标、范围、子区段、分流、评价维度、权重、评分标准及两侧分数的合成方式。 |

- 路径图：新增、移动、修改及删除节点；步骤、决策、开始/结束三种形状；带标签的连接；节点可关联子区段及具体患者分流；缩放。
- 子区段与分流：改名、调整区段顺序、增删，记录不同分流的人数。区段顺序用于编号，图上的连接单独编辑。
- 证据：每个维度保存观察值、评分、引语或理由；每个分流另有洞见、来源与两侧总体记录。
- 讨论记录：保存问题、共识、改进建议、负责人及状态。
- 撤销与重做：当前会话保留最近 30 次编辑。文本输入按一次连续编辑归为一步；刷新后历史不保留。
- 保存与交换：本地自动保存、JSON 完整项目导入导出、CSV 证据表、SVG 路径图、打印报告或浏览器另存 PDF。

## 建议操作顺序

1. 打开论文示例，熟悉路径、子区段与分流的关系。
2. 点击“新建”，在“共同设置”中明确目标、范围和参与角色。
3. 讨论需要哪些维度，以及每项 1–10 分具体代表什么。确定权重，并写下理由。
4. 添加子区段与分流。在“路径工作区 → 编辑路径”中绘制节点与连接。
5. 按分流填写证据、评分和来源。原始分钟数、成本等数值与团队评价分开填写。
6. 查看讨论优先项，回到证据讨论，记录共识与下一步。
7. 下载 JSON 备份。与协作者交换 JSON，由对方通过“打开”恢复完整项目。

## 评分规则

所有维度均按 **1 = 最弱、10 = 最佳** 的方向评分。耗时、成本等原始值不自动换算成评分。

```text
单侧分数 = Σ（评分 × 正权重）/ Σ 正权重
```

只有该侧每个正权重维度都有有效评分时，才计算单侧分数。权重为 0 的维度保留作参照；所有权重为 0 时显示未启用，不生成零分。没有完成的评分不被当作 0，也不与已完成评分混算。

提供两种合成方式：

```text
原版相加（满分 20） = 体验分 + 管理分

加权平衡（满分 10） =（E × 体验分 + M × 管理分）/（E + M）
```

加权平衡中，将某一侧权重设为 0 可明确排除该侧。两侧权重均为 0 时不计算。原版相加要求两侧均完整。排序使用未四舍五入的实际结果，界面显示两位小数；相同分数保持原区段、分流顺序。

人数仅为讨论提供背景，不参与评分、不跨分流求和。不同分流的人数可能重叠。

## 示例如何对应原材料

- 采用论文第 9 章后期的**流程图版本**，保留第 10 章共同讨论评价方式的方向；没有把早期时间线强行变成主界面。
- 7 个子区段与路径分支参照论文图 46 重建。为适应网页，节点文字、形状与布局有所简化。
- S-1 和 S-2 的前三条记录采用 `Peng Lu - Pathway Redesign Tool Example.xlsx` 中的示例数据。其余分流留空，没有补造评分。
- 原 Excel 中存在 `#REF!`、`#DIV/0!` 和分母引用不一致。本版本重新计算，不沿用这些错误。
- 体验权重 3、4、5、2 的总和为 **14**。首组分数 4、5、6、4 的正确加权平均为 **5.00**。原表格部分公式使用了 12 作分母，显示 5.17；论文文字也有相应不一致。网页版在“关于与方法”中说明此修正。
- 示例管理权重为 5、0、4、3、5，总和 **17**；目标时间仅作参照。论文中的另一张图采用目标时间权重 3、总和 20；可在设置中改为该方案，但须先补目标时间的评价依据与分数。
- 原表格为成本、有效性提供了部分评分，却没有给出原始值或明确操作定义。网页版保留空白及说明，区分“已有示例评分”与“已有充分原始证据”。
- 路径图源于论文对 Schertler 等人（2007）的改绘，DOI：`10.1007/s00330-007-0724-9`。该历史例子仅用于演示工具，不作为现行诊疗路径或临床决策建议。

## 部署到 GitHub Pages

本项目没有前端框架、CDN、API key 或后端服务。所有资源使用相对路径，支持独立仓库，也支持放入个人网站的子目录。

### 最简单：仓库根目录发布

1. 在自己的 GitHub 新建仓库，例如 `Pathway_Redesign_Online`。
2. 将解压后的项目内容上传到仓库根目录，确保 `index.html` 与 `src/`、`styles.css` 位于同一层。
3. 进入 **Settings → Pages**，选择 **Deploy from a branch**，分支为 `main`，目录为 `/(root)`，保存。
4. GitHub 完成发布后，在 Pages 设置页点击 **Visit site**。

此方法不需要运行 Node。即使没有上传隐藏的配置文件，也可使用；保留 `.nojekyll` 更直接。

### 可选：GitHub Actions

项目已包含 `.github/workflows/pages.yml`。如选择此方法，在 **Settings → Pages** 中将来源设为 **GitHub Actions**。推送到 `main` 后，会运行评分与数据格式检查，生成 `dist/` 并发布。

两种方式选一种即可。若使用分支根目录发布，可删除 `.github/workflows/pages.yml`，避免多余的工作流运行。

GitHub 官方说明：<https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site>（2026-10-21 查阅）。

### 放入已有个人网站

将 `index.html`、`styles.css`、`favicon.svg`、`.nojekyll` 和整个 `src/` 放入同一目录，如 `Pathway_Redesign_Online/`。无需改资源路径。

## 开发与检查

Node.js 22 或以上；没有第三方包，不需要 `npm install`。

```bash
node --test tests/*.test.mjs
node build.mjs
```

`build.mjs` 生成用于部署的 `dist/`，并重新生成根目录的独立 HTML。修改源代码后需重新运行，才能同步独立文件。

本地 HTTP 预览可用 Python 自带服务：

```bash
python3 -m http.server 8000
```

然后打开 `http://localhost:8000`。

## 保存、隐私与限制

- 当前版本是 **单设备工作区**。自动保存使用浏览器存储，并非云端备份。清除浏览器数据、换浏览器、移动独立 HTML 文件等可能导致无法访问原自动保存，请定期下载 JSON。
- 同一站点的多个标签页共享一份自动保存，可能互相覆盖。需要并行维护多个项目时分别导出 JSON；本版本没有冲突合并功能。
- JSON 保留完整项目；CSV 是分析用导出格式，无法恢复节点、权重设置和讨论。此版本不直接导入原 Excel；原 Excel 用作研究材料与示例来源。
- 没有账号、实时协作、云端同步或生成式 AI。可通过投屏共同讨论，或交换 JSON 文件。
- 不会主动上传填写的数据，也不含分析追踪。GitHub Pages 托管的是应用与附带示例，填写的内容只在访问者本机保存。公开仓库中不要放入含个人身份信息的真实患者数据或 JSON。
- 浏览器“打印 → 另存 PDF”用于输出报告，分页受浏览器影响。
- 编辑上限：100 个子区段、每区段 50 个分流、40 个评价维度、300 个节点、600 条连接。JSON 导入上限 15 MB。
- 论文提出的共同学习过程是未来方向，本网页版没有经过医护团队的实地评估。
